## Что нужно

- Windows, **MSVC** (Visual Studio 2022 или новее, компонент «Разработка классических
  приложений на C++») и **CMake ≥ 3.20**.
- Платформа сборки — обязательно **Win32**: игра 32-битная, и всё, что в неё загружается, тоже.
  CMake остановит конфигурацию, если платформа другая.
- Зависимости подключены как git-подмодули в `third_party/`:

  | | версия | зачем |
  |---|---|---|
  | [MinHook](https://github.com/TsudaKageyu/minhook) | v1.3.4 | перехваты x86 |
  | [ENet](https://github.com/lsalzman/enet) | v1.3.18 | UDP с надёжным и ненадёжным каналами |
  | [SDL2](https://github.com/libsdl-org/SDL) | release-2.32.10 | геймпады в клиенте, статически |
  | [Ultimate ASI Loader](https://github.com/ThirteenAG/Ultimate-ASI-Loader) | v10.0.2 | загрузчик `.asi`, собирается из исходников |
  | [Dear ImGui](https://github.com/ocornut/imgui) | v1.93.0 | окно клиента и служебное окно в игре |

## Сборка

```powershell
git clone --recursive https://github.com/int3re/TMNT-2003-COOP
cd TMNT-2003-COOP
# если клонировали без --recursive:
git submodule update --init --recursive

powershell -ExecutionPolicy Bypass -File tools/build_asi_loader.ps1
cmake -B build -A Win32 -DSTEAMWORKS_SDK_DIR=C:/sdk/steamworks_sdk
cmake --build build --config Release
```

Первая команда собирает Ultimate ASI Loader из подмодуля (его потом CMake кладёт в сборку как
`winmm.dll`). CRT линкуется статически (`/MT`): игрокам не нужен Visual C++ Redistributable.
`steam_api.dll` при сборке проверяется на 32-битность (`tools/check_x86.cmake`).

## Steamworks SDK

SDK скачивается с [partner.steamgames.com](https://partner.steamgames.com/) (нужен бесплатный
аккаунт Steamworks) и **в репозиторий не кладётся**. Из него берутся заголовки
`public/steam/*.h` и 32-битные `redistributable_bin/steam_api.lib` и `steam_api.dll` (не
`win64`).

Без `STEAMWORKS_SDK_DIR` или с `-DTMNTNET_WITH_STEAM=OFF` собирается версия только с ENet
(локальная сеть, VPN, прямой IP) — CMake предупредит об этом.

## Что получается

Готовые файлы — в `build/dist/Release/`:

| Файл | Что это |
|---|---|
| `tmntnet-setup.exe` | установщик; внутри него всё остальное |
| `tmntnet.asi`, `winmm.dll`, `tmntnet.ini`, `steam_api.dll`, `steam_appid.txt` | то, что установщик кладёт в папку игры |
| `tmntnet-client.exe` | клиент режима «игра только у хоста» |
| `alt-loader/dinput8.dll` | запасной загрузчик |

Для релиза достаточно выложить `tmntnet-setup.exe`.

## Тесты без игры

`tests/fake_game.cpp` собирается как подставной `tmnt.exe`: он загружает настоящий
`tmntnet.asi` и опрашивает клавиатуру DirectInput так же, как игра. Скрипты завершаются кодом 0,
только если прошли все проверки.

| Скрипт | Что проверяет |
|---|---|
| `tests/run_integration.ps1` | клиент → ENet → перехват → клавиши игрока 2 (`PASS`) |
| `tests/run_steam_mock.ps1` | логику Steam на моке, без Steam и аккаунтов: вход в лобби по SteamID хоста, отказ чужаку, жёсткое завершение клиента и перезапуск, выход с прощанием, Hello раньше членства в лобби, 10 % потерь и 40 мс задержки, молчаливая смерть клиента (`ALL OK`, 13 проверок) |
| `tests/run_chaos.ps1 -ChaosDir <папка>` | путь LAN/IP через «плохую сеть» из [coop-anything](https://github.com/cranebeaker/coop-anything/tree/main/tools/chaos) и обрыв на 2,5 с посередине |

```powershell
powershell -ExecutionPolicy Bypass -File tests\run_integration.ps1
powershell -ExecutionPolicy Bypass -File tests\run_steam_mock.ps1
```

**Мок Steam** (`[net] transport=mock`, `mock_slot`, `mock_dir`, `mock_loss_pct`,
`mock_latency_ms`) — подмена внутри мода, а не подмена `steam_api.dll`: фальшивые SteamID,
сообщения по localhost, лобби и участники — файлы с отметками времени. Он проверяет логику
tmntnet, но не сам Steam: ретрансляторы, NAT и настоящую `steam_api.dll` проверяет только игра
с двух аккаунтов.

<details>
<summary>Что нашли эти тесты</summary>

Уже исправлено:

- мок, порядок «Hello раньше членства в лобби»: принятый из ожидания игрок тут же сбрасывался
  «за тишину» — беззнаковая разность времени ушла в минус;
- хаос `hell`: хост рвал ENet-соединение после обрыва, а клиент со стандартными тайм-аутами ENet
  (до 30 с) этого не замечал и не переподключался — тайм-ауты теперь одинаковые с обеих сторон;
- хаос `bad_wifi`: троттлинг ENet после всплеска RTT резал ненадёжные пакеты ввода — выключен.

</details>

<details>
<summary>Правила Steam-транспорта, которые они проверяют</summary>

Steam-транспорт поверх ISteamNetworkingMessages (правила из coop-anything, `playbook/networking-steam-spacewar.md`):
- у каждого сообщения 4-байтный ID запуска отправителя: перезапущенный клиент (тот же SteamID)
  начинает новую сессию, а опоздавшие пакеты старого запуска отбрасываются;
- keep-alive раз в секунду, игрок, молчащий 10 с, отключается; закрытие — служебным bye;
  выход из лобби (LobbyChatUpdate) тоже отключает игрока;
- все отправки без Nagle; `static_assert`, что отправитель в `SteamNetworkingMessage_t` на x86
  лежит по смещению 12 (как в настоящей 32-битной `steam_api.dll`);
- приглашения: свой список друзей в окне игры и `InviteUserToLobby` (оверлей Steam выключен,
  а в старых D3D9-играх его диалог и так не открывается), rich presence
  `connect=+connect_lobby <id>`, `GameLobbyJoinRequested` и `GameRichPresenceJoinRequested`
  у клиента, ID лобби с копированием;
- клиент при тишине хоста заново входит в лобби (а если лобби пропало — ищет новое лобби хоста).

</details>

**Внешний вид без игры:** `build/tests/Release/ui_preview.exe <папка>` рисует служебное окно
мода на тестовых данных в PNG; `tmntnet-client.exe --screenshot окно.png` сохраняет окно клиента.

## Лаборатория: прогоны в игре

Всё, что касается lockstep, проверяется на **нескольких копиях игры на одном ПК**: копии папки
игры с разными портами (или слотами мока Steam), которые играют одну сессию по заранее
заданным нажатиям. Потом их журналы кадров сравниваются.

> [!WARNING]
> Запускайте такие прогоны только на **копиях** папки игры, не на основной установке: они
> переписывают `tmntnet.ini` и сохранения.

Ключи раздела `[debug]` в `tmntnet.ini`:

| Ключ | Что делает |
|---|---|
| `multi_instance=1` | разрешить несколько копий игры одновременно |
| `light=1` | ожидание кадра спит, а не крутит ядро на 100 % |
| `autostart=1` | мод сам проходит заставку до главного меню |
| `frame_log=1` | журнал кадров `tmntnet-frames.log`: состояние `rand()`, число вызовов, кнопки |
| `rand_trace=1` | в журнал кадров — адреса возврата всех вызовов `rand()` |
| `frame_keys=кадр:DIK:длительность,…` | «нажать» клавишу (код DirectInput, hex) на кадре сессии |
| `shots=menu:мс,csel:мс,press_XX:мс,…` | снимки кадра и нажатия по времени от главного меню или экрана выбора |
| `stage=N` | на карте уровней начать уровень N |
| `stage_over_at=кадр` | на этом кадре уровень считается пройденным (родной флаг игры): переход на следующий без прохождения |
| `session_seed=N` | хост начинает сессию с этим зерном (повторить прогон) |
| `camera_trace=1` | дважды в секунду — камера и места игроков в лог |
| `level_dump=1` | статика игры в начале и в конце уровня — в файлы (что уровень оставляет после себя) |
| `profile=1` | выборочный профиль игрового потока во время догона |
| `stall_at=N`, `stall_ms=M` | игровой поток засыпает на M мс (проверка сторожа зависаний) |
| `auto_ready=0` | гость не нажимает «Я ГОТОВ» сам |

Сравнить журналы двух копий можно простым скриптом: первая строка, где различается состояние
`rand()`, — кадр расхождения, а разница в списках адресов показывает, какой код отработал
по-разному.

Что стоит прогнать после изменения, затрагивающего логику:

1. две копии по ENet, уровень целиком и переход на следующий;
2. три–четыре копии через мок Steam с приглашениями;
3. выход и возврат одной из копий посреди уровня;
4. принудительную перерисовку и сворачивание окна одной из копий;
5. копии с разным размером окна (16:9 и 4:3).

Во всех случаях журналы кадров должны совпасть до последнего общего кадра.

## Флаги клиента

```text
tmntnet-client.exe [код | ip | SteamID64 | ID лобби] [+connect_lobby ID]
                   [--nogui] [--test] [--no-input] [--seconds N] [--screenshot файл.png]
```

`--test` — клиент сам нажимает вправо, влево и прыжок: проверка без геймпада.

## Проверка через Steam вживую

Мок не заменяет настоящий Steam. Перед релизом, меняющим сеть, нужна игра с двух (лучше
трёх–четырёх) ПК и аккаунтов, желательно в разных сетях:

1. хост: в логе `Steam ready`, `Steam lobby … created`; друг видит игру и входит по приглашению;
2. сюжет проходится хотя бы несколько уровней, в логах всех ПК нет `DESYNC`;
3. один игрок выходит посреди уровня и возвращается;
4. у одного игрока выдёргивается сеть на несколько секунд;
5. Steam закрыт → на странице «СТИМ: ВЫКЛЮЧЕН», после запуска Steam мод подхватывает его.
